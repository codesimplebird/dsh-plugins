# 第五轮：状态栏逐轮 TPS（2026-11-19）

## 背景

用户要求状态栏（输入框下方 14 轮 404 步 · 231 tok/s）**加上每轮 tps**，因为累计平均几乎不动。

## 根因定位（查了 asar）

- 渲染组件：dsh-client-ui-chat 的 ActivityPill，挂在 slot conversation.composer.dock（id ctivity，order 0）。
- 文案词条：stats.counts = "{turns} 轮 {steps} 步"，速度来自 decodeSpeed(stats,t) → message.tokensPerSecond = "{tps} tok/s"。

### 第八轮：胶囊只显示运行中数量（2026-11-20）

**需求修正**：上一轮理解错了。用户要的不是「面板里隐藏已完成行」，而是
**胶囊上的数字只统计正在运行的子智能体**，点开面板仍可查看全部（含已完成）。

**处理**：
- 卸掉 `dsh-hide-completed-subagents`（源码保留在 `~/.dsh/plugins/`，已从 profile 移除）
- 新插件 `dsh-subagent-running-count`（v0.1.1）

**实现依据**（读 `dsh-client-ui-subagent` 源码得到）：
- 胶囊：`<span data-subagent-count>{t(totalCountKey,{count:directCount})}</span>` —— 渲染总数
- 同时存在隐藏无障碍 span：`{variant==='count' && runningCount>0 && <span hidden>{t(runningCountKey,{count:runningCount})}</span>}`
  —— 运行中数量已在 DOM 里，无需重算投影
- 关键位置细节：该 span 是**按钮/fragment 的兄弟节点**，不是胶囊的子节点，所以要从胶囊向上找 2~3 层，
  在**直接子节点**里匹配 `:scope > span[hidden]`

**规则**：文本匹配 `正在运行|running` → 取数字 → 胶囊改为 `N 个运行中`；无运行中则清空数字只留图标
（`SHOW_ZERO=true` 可改为显示 `0 个运行中`）。
`MutationObserver`(childList+characterData+subtree)+rAF 去抖重写，文本已正确时不写，避免循环。
隐藏 span 只在 running>0 时存在，故用 WeakMap 记录「曾读到过」，之后缺失才判定为 0，避免结构异常时误判。

**验证**：`node --check` 通过；源与已装副本哈希一致；配置解析 1372 行、0 异常；
`subagent-running-count` 已进 bundle 列表与配置树；旧插件已从 node_modules 与 bundles 移除。

**边界**：DOM 耦合（官方改结构则保持官方总数、不报错）；只识别中英文；不影响数据与历史访问。


### 第九轮：胶囊计数改为「运行中」（v0.1.2 诊断版）

**现象**：用户重启后胶囊仍显示「3 个子智能体」。

**分析**：读编译产物（`dsh-client-ui-subagent/lib/client.js`）确认结构：

```jsx
<div or fragment>
  <Tooltip label={t(totalCountKey,{count:directCount})}>
    <button aria-label={t(totalCountKey,{count:directCount})}
            aria-describedby={variant==='count'&&runningCount>0?activityId:undefined}>
      <span aria-hidden><IconUsers/>{runningCount>0 && <StateDot state="ongoing"/>}</span>
      <span data-subagent-count>{t(totalCountKey,{count:directCount})}</span>
    </button>
  </Tooltip>
  {variant==='count' && runningCount>0 && <span id={activityId} hidden>{t(runningCountKey,{count:runningCount})}</span>}
  {open && createPortal(<MenuSurface .../>)}
</div or fragment>
```

结论：**隐藏的运行中 span 只在 runningCount > 0 时渲染**。如果当时没有运行中的子智能体（截图里三个都是历史记录），
该 span 不存在，而 v0.1.1 的守卫逻辑选择「没读到过就不动」→ 保持官方总数。

**v0.1.2 修改**：

- `SHOW_ZERO = true`，显示 `0 个运行中`，同时作为「插件是否生效」的可见诊断信号

**验证**：`node --check` 通过；源与已装副本哈希一致；配置 1372 行 0 异常。

**下一步诊断**：重启后看胶囊文案
- 显示 `0 个运行中` 或 `N 个运行中` → 插件已加载，逻辑正确

### 第十五轮：修复 v0.3.1 完全失效（v0.3.2）

**现象**：v0.3.1 重启后，花名册**既没有时间、也没有折叠**，退回原生样子。

- 排序/时间/折叠互相隔离，各自 try/catch，任一失败不影响其余

### 第十六轮：真实 DOM 结构是 wrapper 包裹，导致排序/折叠失效（v0.3.3）

**现象**（用户截图）：时间列生效了（fiber 读取 OK），但**顺序没反、没有折叠**。

**根因**：官方每一行外面还有一层 `<div class="node">`：

```jsx
<div className={css.node}>
  <div role="treeitem"> … </div>
  {expanded && <div role="group">…children…</div>}
</div>
```

v0.3.2 按「行的 `parentElement`」分组，而每行的父元素就是这个 wrapper（只含一行），
于是每组 blocks.length === 1 → 不排序；根列表 blocks 数也按 1 算 → overflow=0 → 不折叠。
（v0.3.0 的折叠之所以有效，是因为它直接在扁平行列表上按索引隐藏。）

**修复（v0.3.3）**：
- 新增 `commonContainer(rows)`：从 `rows[0].parentElement` 向上找**包含全部行**的最深祖先
- `collectBlocks(container)`：按容器的**直接子节点**切块——能查到行的子节点开新块（行本身或它的 wrapper），
  其余节点归入当前块的 `trailing`（嵌套 group 随之移动/隐藏）
- 排序键取块内**首个行**的 `createdAt`；折叠时对整块（wrapper + nested group）设 `display:none`
- 这样两种结构（有/无 wrapper）都能工作

**测试**（真实 Chrome，三种结构）：
| 结构 | 顺序 | 可见 | 时间 | 折叠 |
|---|---|---|---|---|
| A 每行 wrapper（真实结构，复现本轮 bug） | 9→0 | 9..2 | ✓ | 显示其余 2 条 |
| B 无 wrapper | 9→0 | 9..2 | ✓ | 同上 |
| C 真实结构 + 一行展开含嵌套 group | 9→0 | 9..2 | ✓ | 同上 |

展开后可见 10 条，按钮变「收起较长列表」。胶囊冒烟 12/12；已装副本回归同样通过。
v0.3.3，配置 1372 行 0 异常。另生成预览截图（真实 wrapper 结构）供用户先看效果。

### 第三十二轮：修复「回合结束后任务面板仍显示未完成」（dsh-todo-finalizer v0.1.0，2026-11-24 23:10）

**现象**：对话已经结束，输入区上方的「任务」面板仍显示「1 已完成 · 2 未完成」，过了一段时间/用户问起才清掉；
这个问题反复出现过几次。

**根因（查证）**：那个「任务 N 已完成」是 `TodoDock`，数据来自会话的 `todos` 投影
（`@deepseek-ai/dsh-tool-todo` 注册）。该投影的规则是：`todo/write` 覆盖、**`turn/start` 时清空、`turn/end`
保留最后清单**（"turn/end keeps the finished checklist visible"）。所以只要 agent 在回合结束前最后一份
todo_write 里还留着 pending/in_progress，面板就会一直显示未完成——不是渲染 bug，是收尾数据没更新。

**修复**：新 host 插件 `plugins/dsh-todo-finalizer`（**v0.1.0**，无浏览器半）：
- 订阅 `ctx.on('agent/created')`，再对每个 agent `agent.ctx.on('session/event')`；
- 记录本回合最后一份 `todo/write` 清单（含所属 turn）；
- 当 `turn/end` 且 `reason.kind === 'completed'`、且该清单仍有未完成项时，用 `queueMicrotask`
  延后追加一条 `todo/write`，把全部项标为 `completed`（避免在事件分发中重入会话日志）；
- 只收尾**本回合**写的清单；aborted / blocked / error / max-tokens 的回合保持原样（未完成是真实的）；
- 同一回合幂等、异常全部吞掉，不影响回合本身。

**验证**：
- `node --check` OK；纯 Node 单测 `test/finalizer.mjs` **ALL_PASS=true**：completed 回合收尾（全部 completed）、
  aborted 不动、已完成清单不动、上一回合清单不动、重复 turn/end 只追加一次；
- 安装：deps=14 / bundles=16；临时 profile `--dump-config` **exit 0、2198 行**，`todo-finalizer` 行在配置树里，
  无新增异常；备份 `backups/desktop-*.before-todo-finalizer-20261124`。
